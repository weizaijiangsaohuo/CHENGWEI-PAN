# Starflow AI · 社区真实数据与空状态修复（阶段 2.1）

## 查明的问题

- 当前项目 Supabase 公开帖子数据表为 **0 条**，账号表 4 条，通知表 3 条。这是检查时的状态，随使用会变化。
- 之前“帖子”标签未输入关键词时，前端直接赋予空结果，即使数据库日后有真实帖子，也会显示一块无内容区域。
- “全部”“话题”“帖子”在无公开帖子时重复展示空卡片和大面积留白，未说明是初始社区无内容。
- 原首页及主页的通用空状态有巨大装饰性符号，与用户上传的 X 式信息流参考图不符。

## 这次实改

1. 修改已有 `StarflowDiscoveryPhase2.tsx`（**覆盖原文件，不新增第三层搜索组件**），保留旧通知、帖子详情分享和搜索账号功能。
2. 搜索保留用户名里的下划线（例如 `pcwgf_1437021`），未输入关键词时真正查询最近 30 条公开原创帖子，而不是返回代码写死的空数组；输入关键词时照常搜索最多 60 条结果。
3. 若数据库没有公开帖子，显示唯一的说明区、真实发帖入口，并保留可点击的真实用户列表。帖子出现后，自动显示最新公开帖子与从最近 150 条公开帖计算的话题。
4. 探索页用户列表直接关注/取消关注：复用原有 `follows` 行级授权写入，失败显示错误；不虚构关注成功。
5. 读取失败时提供“重新加载”；全站通用帖子空态缩小装饰图标，减少巨大留白。
5. 不编造热搜、帖子、浏览量、通知。不恢复用户之间的私信。

## 已知范围及验收

- 只修复 **真实数据展示与相关交互和样式**；尚未实现浏览次数、后端提及通知生成、完整分页和推荐算法。
- 现有发帖数据库写入、粉丝、个人资料、媒体上传及三色认证机制不改；**无数据库迁移**。
- 必须在 GitHub TypeScript + Next.js 构建后，用 iPhone 测试：探索全部显示真实账号和社区状态；进入“帖子/话题”只有一个解释；发布一条公开文字动态后，重新进入“全部/帖子”能显示它，搜索关键词能找到它；通知依然正常；个人主页空态不再出现大型绿色符号。
- 如果真实发布后帖子不出现，应查看发布后的服务端错误或 RLS 记录，不能用演示卡片代替。
