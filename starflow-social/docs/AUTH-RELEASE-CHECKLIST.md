## 每次发布及认证配置变更前
- [ ] 确认正确的 Supabase 项目和已部署版本，不把 GitHub CI 结果当成部署证明。
- [ ] SMTP 使用有效应用专用凭据；发送真实测试邮件，确认收件箱收到且无退信。凭据仅保存在授权服务端配置，不写入仓库、日志或聊天。
- [ ] 核对 Site URL 和精确 Redirect URLs：当前测试与正式环境按实际使用项目分别授权 /auth/confirm 及必要的其他回调。不使用任意域名通配符，不删除仍使用的旧地址。确认注册模板最终渲染出的真实链接进入 /auth/confirm，且保留正确的 token_hash 和 type=email；不记录或共享令牌值。
- [ ] 新邮箱注册、人机验证、收件、点击新验证链接、后台 email_confirmed_at 写入、实际会话建立并自动进入会员页面。
- [ ] 未验证邮箱无法登录；重发需新的人机验证，防止重复发送、保留服务端限流；验证链接过期或失效时提供重新发送指引。
- [ ] 重复提交、刷新、跨设备同邮箱注册不能创建重复账号，也不能透露无关账号是否存在；网络中断后检查真实结果，不盲目重复注册。
- [ ] iOS Safari、Android Chrome、桌面浏览器及常用 App 内置浏览器：注册、邮件跨浏览器打开、登录后停留、刷新、返回、重新打开、主动退出。记录实际结果；未测试的平台不得宣称通过。
- [ ] 认证和安全检查通过，无新增付费服务，保留原有 Worker 和业务数据。

## 故障处理
1. SMTP 535：先查认证日志、修复发件凭据；不要关闭邮箱验证。
2. 邮件未到：分别核对后端发送记录、发件和退信、实际收件，HTTP 200 不证明最终投递。
3. 点击链接返回首页：核对实际邮件链接的主机、路径及参数名称（不记录令牌），以及允许跳转地址与真实 /verify 记录。
4. 登录凭据无效：核对项目和登录输入，提供安全找回密码流程，不替用户直接改密码。
5. 页面异常返回首页：记录浏览器与已部署版本，区分网页内状态切换和宿主关闭网页；修复后复测。
6. 任一核心项失败时停止上线，保留可回滚版本和数据；不得伪造验证成功或绕过人机验证。

本文件是发布操作规范，不是自动化发布阻断器；执行记录与真实环境复测仍然必需。
