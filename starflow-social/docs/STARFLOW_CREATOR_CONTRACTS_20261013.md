# Starflow 创作者在线合作签约 · 2026-10-13

## 业务闭环

1. 获授权的官方运营人员在 `/admin/contracts` 可人工查看最近 90 天主帖数、近 90 天作品获赞数和真实关注者数量，点击作者主页评估实际内容原创性和质量。指标不保证真人粉丝、版权或合作资格。
2. 只有创始人和超级管理员可填写真实平台法定签约主体、个别化完整协议、人工筛选理由、有效期限（3—30天）、可选的真实作品 ID，并“一键联系并发送签约邀请”。
3. 数据库生成不可改写的协议正文快照和 SHA-256 指纹，并写入邀请操作记录及收件创作者的站内通知。
4. 创作者通过 `/contracts` → `/contracts/[id]` 查看，完整审阅后自行输入签署姓名并勾选明确同意。拒绝则状态“declined”；逾期禁止签署。
5. 签署后仅创始人或超级管理员能复核全文并使用个人姓名再次明确确认复签，状态才变为“completed”；创作者收到站内通知。
6. 双方留存不可编辑的条款快照、指纹、服务器记载的签署时间与追加式事件记录，用户可通过浏览器打印/另存协议。平台可在**未完成**前撤回邀请并通知创作者。

## 权限与数据边界

- Supabase 两表均 RLS，仅签约本人及创始人/超级管理员可 SELECT 协议/审计事件。
- 表不给浏览器 INSERT / UPDATE / DELETE 权限；全部写入必须通过认证且角色检查的 SECURITY DEFINER RPC。
- 创作者无法替另一账号签署，无法同意过期邀请，无法跳过勾选或填写名字。
- 平台不能在创作者签名前复签；禁止同一账号自己邀请自己；最多同一创作者1条开放邀请，同一平台签约管理员24小时不超过30份。
- 已发出协议的正文、签约主体、作品、指纹、创建时间和到期时间经数据库更新触发器保护，不允许被偷偷改写。
- 只发送通用站内通知，不含协议私密条款、签署姓名或个人身份信息。不公开签约协议或签署记录。
- 不收集完整 IP、身份证号码或手机号以签约。当前签署为账号登录 + 勾选确认 + 输入姓名 + 服务器时间/哈希的**普通平台内签署流程**，不是符合某法域全部要求的身份核验、CA 数字证书或第三方可信时间戳。

## 签约前必须准备的合法内容

不得虚构平台的法人主体。管理员在发送时必须使用有签约资格的主体、经专业审核的明确条款，包括但不限于：
- 双方真实合同身份及联系与送达方式
- 合作作品的版权归属、授权范围、地域、期限、是否独家、再许可限制
- 收益分成/固定报酬、计价方式、结算周期、税费与违约
- 数据处理/保密、安全与投诉途径
- 解约、违约、争议解决与适用法律

如需要符合中国电子签名法意义上可靠电子签名、强身份鉴别、可信时间戳、法律取证与合同履行能力，应接入合规电子签约/CA 服务后再对外宣传“具有相应法律效力”。当前版本不宣称第三方认证、不可抵赖法律保证或自动版权转让。

## 验证与上线

- staging SQL 迁移成功；两账号模拟平台邀请→创作者明确同意签署→平台复签，状态 `completed`、64位指纹、3条事件均通过。测试事务已 ROLLBACK。
- staging 未授权第三账号读取指定合同时返回 0；无同意签名被拒绝；无直接表写入。
- 所有前端页面应通过 GitHub / Cloudflare 构建后才合并；合并后的正式库迁移必须再次检查 RLS、授权和生产状态。
- 需要至少2个真实非测试账户人工确认 iPhone Safari 和桌面表现，才能宣称完整真机验收。
- 之前披露的服务器高权限密钥尚未轮换，新增签约功能不解除该风险。
