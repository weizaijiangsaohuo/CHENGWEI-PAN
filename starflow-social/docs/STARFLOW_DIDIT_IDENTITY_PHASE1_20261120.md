# Starflow 身份核验与反欺诈 — Didit 接入一期（未启用）
日期：2026-11-20。唯一外部 KYC/KYB/AML 供应商：Didit。账户认证另由 Better Auth/WebAuthn 迁移项目负责。现有三色徽章、Supabase、线上配置不修改；不允许将 KYC 状态自动映射为蓝/金/灰徽章或管理员权限。

## 本次实现
- 服务端签名校验（原始字节 X-Signature，HMAC-SHA256，时间窗 300 秒）、事件范围约束（应用、环境、工作流及版本），精简事件结果。
- 固定 HTTPS API 的只读核验查询；不转发原始报告、照片或媒体链接。
- 校验服务器记录的随机关联编号、session ID、工作流 ID、节点 ID；要求证件、主动 3D 活体、人证比对均 Approved。若配置 AML，必须无命中及无警告，否则人工复核。
- 未注册生产接口；不创建真实核验会话，不调用充值或付费模块。尚未实现持久化去重、身份绑定、预算预留、认证入口或真实 sandbox 验证。本次代码不授予任何账户权限。

## 下一期必要门槛（缺一不得上线）
1. 由所有者独立注册 Didit，使用可恢复邮箱、MFA；先建 sandbox 应用及发布 KYC 工作流：证件 + Active 3D Liveness + Face Match，可按实际合规义务单独配置 AML。禁止将被动活体或仅上传自拍当作通过。锁定工作流版本和节点 ID、禁止在正式工作流中悄悄添加收费模块。
2. 确认免费资格和控制台当前账单政策（2026-11-01 已调整），不绑卡、不充值、不允许负余额或自动扣款；若无法确认服务端硬停止则禁止生产调用。报价基础含主动活体及 AML 为 58 美分/次，10 美元约 17 次，不构成实际保证，重试与其它模块另计。
3. 新身份数据库设计：账号及随机 attempt UUID 绑定、唯一 session ID、环境/应用/工作流版本隔离、事件 ID 唯一约束、状态变更原子事务、管理员审计、撤销/到期、供应商数据删除与用户申诉。不可用客户端传入的 user_id、状态、价格、版本。并发额度预留与真实账单对账；未知外部请求结果保留预留，禁止盲目重试。验证单次最大成本及供应商的重试计费，无法可靠约束则暂停。
4. 所有 API 私钥和 webhook secret 仅存 Cloudflare Worker Secrets，不进公开 GitHub、NEXT_PUBLIC 变量、聊天、日志或截图。认证启动只限已登录用户、同源校验、速率限制、明确单独同意；创建会话只用服务器固定工作流及回跳地址，验证返回 URL 的 HTTPS 主机；回跳不是认证成功凭证。
5. Webhook 原始字节限长、验签后持久化事件去重、绑定环境和账号；查询服务端真实决定并防止旧事件覆盖新状态；人工处理风险误报。正式环境必须拒绝 sandbox 数据。
6. 隐私/合规审查：人脸及证件属敏感信息；确认必要性、合法基础、跨境合规、适龄安排、服务商数据处理协议和删除期限、真实用户撤销/申诉渠道。只保存必要最少状态，禁止将人脸、身份证原图、姓名/生日、媒体链接上传公开仓库。AML 不等同监管认证；不因匹配名单自动认定违法。普通注册登录不强制 KYC（依法必须的场景另行审批）。
7. 独立测试环境验证异常操作、真实相机/活体、人证差异、重放/伪造回调、重复与乱序事件、成本限制、撤销/到期、手机浏览器体验，通过后才审批部署。旧 Supabase 数据不可擅自删除；待后端迁移后再接入正式账户。
