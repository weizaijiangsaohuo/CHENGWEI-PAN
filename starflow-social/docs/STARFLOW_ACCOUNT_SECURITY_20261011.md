# Starflow 账户安全中心 · 测试版交付
基于四份产品需求文件中“密码、当前邮箱、第三方绑定及账号找回”要求实施。本次仅修改 PR #2 测试分支，正式环境及注册确认邮件不改。

## 完成
- 设置页面新增 /settings/security 安全中心入口；登录用户可查看 Supabase Auth 中本人邮箱、验证状态和真实身份提供商关联。
- 邮箱密码用户修改密码时提交旧密码 `current_password` 给 Auth 后端验证，密码不得仅在浏览器比较；OAuth-only 且已验证邮箱的账户可首次设置邮箱密码。
- Google、Apple、Facebook、X 使用 Supabase Auth 原生 OAuth 绑定 `linkIdentity`，与登录 `signInWithOAuth` 分开。配置标识启用后，相应平台也出现在登录页，才可能成为找回渠道。
- 微信、QQ 标注为“待接入”，需官方开放平台授权和可被 Supabase Custom OAuth/OIDC 使用的认证提供商；只有真实配置后才开放绑定与登录。
- 已验证邮箱的找回入口调用 Auth reset API；成功发起请求不等于 SMTP 实际投递成功。
- 不允许安全中心任意解绑最后一种登录方式。回调重定向使用最长 10 分钟有效的同浏览器 marker，只允许本地精确路由。

## 限制
- Supabase Auth Manual identity linking 与各 OAuth provider 的 App Credentials 仍需在管理端开启；当前已连接 Supabase 管理接口不支持直接写入相关配置。请勿将“代码完成”当成第三方接口已上线。
- 不能用未经验证的 QQ/微信号当做找回账号的证据；绑定身份认证必须以各提供商签发的令牌为准。
- 真实邮件找回验收需要待邮件服务可用后完成，目前确认注册邮箱验证仍暂停。
- 密码安全、跨浏览器 OAuth 回调、多平台绑定需真人测试；生产上线前建议启用 Auth 强制当前密码 / MFA 和异常登录审计。

## 验收清单
- [ ] 同一个 Starflow 用户登录后正确显示其邮箱及全部关联身份；其他用户不能读取。
- [ ] 原密码错误时 Auth 后端拒绝更新；原密码正确、两次新密码一致后可生效；异常不回显密码。
- [ ] OAuth-only 且已验证邮箱的账号可安全地设置密码，未验证账号不可。
- [ ] 未配置的 Apple/FB/X/微信/QQ 不允许触发虚假 OAuth。
- [ ] OAuth 关联结束后 User ID 与登录前一致，列表刷新显示对应平台；可使用该已关联平台重新登录。
- [ ] 认证/找回邮箱相关行为按实际发件结果验收，而非只看请求返回。
