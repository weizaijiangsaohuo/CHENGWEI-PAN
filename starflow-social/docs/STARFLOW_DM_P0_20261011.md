# Starflow 一对一真实私信 · 测试分支交付说明
本模块基于用户提供的《X_UI_Full_Guide》UI/UX 规范和《X平台完整开发需求说明书》开发，保留 Starflow 独立品牌。

## 已实现
- 原 `/messages` 误跳客服入口替换为真实独立会话/消息页面，支持桌面双栏和手机会话列表→独立聊天页。
- 首页左侧/移动底部导航新增私信入口，访问其他用户主页提供「私信」按钮；支持搜索用户名开始会话。
- staging Supabase 新建 `dm_conversations`、`dm_messages`、`dm_read_state`，会话唯一双人组合；消息 1–2000 字。
- 会话双方之外的用户和匿名访问者不能读取消息/未读回执；写入仅限对话参与者，禁止客户端冒充发送者；消息不可从浏览器任意篡改。
- 收件箱与消息 10 秒轮询、标记已读、发送中的反馈、发送失败提示、断点适配和刷新后会话留存。
- API 权限是数据库 RLS 和经身份检查的 RPC，界面隐藏按钮不是权限依据。

## 已知剩余
- 双账号跨浏览器的真实消息收发/私密性端到端验收仍需测试后才能标记「已验收」。
- P1 群聊、图片/视频附件、消息请求、拉黑/静音、防骚扰设置、精细分页（当前每次最近 100 条）与服务端实时推送尚未实现。
- 目前采用授权查询轮询，不是 websocket 推送，也不是端到端加密；不能向用户宣称 E2EE。
- 聊天入口可能出现短暂等待，页面必须展示错误而非虚构聊天数据。
- 仅部署到测试分支和 Supabase starflow-staging，邮件配置保持暂停、生产站禁止变更。

## 验收
1. 账号 A 从账号 B 主页点击私信，创建会话；搜索 username 可进入同一会话，无重复。
2. A 发送消息，B 在另一浏览器约 10 秒内可读；刷新/重新登录后可保留。
3. 收到新消息的 B 显示未读标识；进入会话后已读标识清除。
4. A/B 可见消息，非参与者 C 不可 SELECT 或 INSERT 同一会话的消息；伪造 sender_id 被拒绝。
5. 断网发送失败保留输入草稿，禁用重复发送；测试 0 字符、2001 字符不能写入。
6. iPhone Safari：会话列表打开详情、返回、滚动、软键盘、输入和提交按钮无遮挡。
