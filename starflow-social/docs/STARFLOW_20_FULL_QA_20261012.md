## 本阶段新增

`/diagnostics`：在手机或桌面浏览器 **用户主动点击** 后，检查：
1. 同源 `/api/health` HTTP/JSON 响应与基础环境配置状态（不执行数据库写入）。
2. HTTPS、WebRTC 和媒体设备**接口存在性**；不打开摄像头、不请求麦克风权限。
3. WebSocket、Notification 权限当前状态、Service Worker/Push API 能力。
4. Canvas/MediaRecorder 和 MP4/WebM 支持检测，不假设原生 4K/120FPS。
5. 系统分享、IndexedDB、Blob URL 以及临时 sessionStorage 可读写。
6. 本地显示结果、复制报告；报告不包含敏感账户信息、密钥、文件内容、麦克风音频。
7. 入口仅放在账号设置，不增加截图里已简化的首页主菜单负担。

**以上仅为基础能力检测，不是音视频通话成功、通知真正送达或服务器数据一致性的证明。** 浏览器自动化与真机操作是两个不同的验证层级。

## 验证步骤

1. CI：运行 `npm run check`, `npm run lint`, `npm run build`（GitHub Actions）。
2. Deploy：确认当前 main 提交的 Cloudflare Workers Builds 状态成功。构建成功**不等于用户网络可访问**。
3. 真机 Safari 打开线上站点，登录后进入「设置 → 设备与服务自检」，点击「开始完整自检」并记录截图。
4. 逐项执行上表真实业务流，记录有明确时间和设备环境的复现步骤；禁止直接把接口检测绿灯当作消息发送成功。
5. 关注免费套餐限制和服务器限流；本次没有购买 GPU、推理 API 或新增第三方订阅。
