# Parallel release acceptance (phases 2–5)
All work streams proceed in the existing feature branch. No production activation, new Worker, paid resources or legacy deletion is authorized by a successful CI build alone.
- Account: CI exercises verified sign-in through the same guarded dispatcher, real restricted Postgres sessions, TOTP and WebAuthn ceremonies, mail callbacks and rate limits. Actual preview sign-in, passkey routing with staff MFA policy, authenticated enrollment, live mail provider and safe account recovery remain separate gates.
- Social: integrated real-session fixture covers posts, likes, comments, private messages, notifications and logout; sync tests validate pagination and account switching. Live WebSocket service and existing UI integration remain gates.
- Identity/admin: CI covers limited metadata, scope-bound single-use proof and audit. Sensitive identity storage remains disabled until provider verification, consent/retention/deletion and authorized review/key custody requirements are met. Separate role connections are required; business login must not gain review grants.
- Migration/media: offline inventory and post mapping tests run with service CI; no legacy source backup is available in this branch. Source reconciliation, media copies, identity recovery and rollback remain mandatory, not assumed.
- Existing preview: live owner readiness was observed successful on 2026-11-21 for commit 99ab764; CI is not proof of subsequent live deployment. Rotate disclosed preview credentials securely before activating features. Production cutover remains blocked until independent acceptance and a verified backup/rollback.
