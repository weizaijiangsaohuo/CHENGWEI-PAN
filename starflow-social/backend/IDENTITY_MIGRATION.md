# Identity and migration rollout gate
Sandbox persistence only: attempts bound to principal and provider session, one pending attempt per user, event ID deduplication and revision compare-and-set. No live environment can be entered. Only test database owner has access. The Didit adapter on PR #58 must verify raw-body signature and fetch current provider decision before any call; event recording alone does not mean processed. Actual worker needs transactional durable outbox, retryable claimed/processed state, provider timestamp ordering, revocation and deletion, quota enforcement, and authorization. Terminal state is not a public badge or proof of continuing eligibility. No biometric media or document contents stored. No provider requests in tests.
## Legacy migration
1. Keep legacy source and Cloudflare secrets untouched. Inventory authorized exports only: auth users, profiles, posts, followers, likes/bookmarks, DMs, restrictions, admin grants, storage metadata. If no lawful export available, no claim of recovered data; obtain owner decision before fresh database activation.
2. Keep stable UUIDs for authorized source principals. Auth subjects are new, never infer binding from emails/handles; verified recovery or separate new account. Export files never enter public GitHub. No legacy password hash copy or self-service founder recovery.
3. Dry run staging with counts, uniqueness, FK integrity, restricted visibility, blocked pairs, private messages, admin role and media checks. No connection to inaccessible legacy service with copied secrets. No production writes.
4. Rollout: verify new service free limits, backups and restore, auth and permissions, media/realtime, scheduled jobs, all original business features. Maintenance window with rollback; preserve original state. Then remove old runtime dependencies and owner removes obsolete secrets. No deletion of old data or provider account.

## Executable inventory gate
Run backend/migration/legacy-inventory.sql on an authorized read-only legacy backup. Export the single legacy_inventory JSON value locally (not into GitHub), then run `node backend/migration/compare-inventory.mjs inventory.json`. It outputs table-level counts and known schema differences, never content. Missing core tables, malformed input and nonempty unsupported tables are explicitly reported. Exit 2 means cutover blocked even with a valid inventory; exit 1 means invalid input. The legacy schemas currently include attachments, replies, polls and community fields that require additional mapping. This is inventory only: no automatic data import or deletion. A source backup and independently verified target reconciliation remain required.

## Legacy post mapping
`planLegacyPosts` accepts an authorized local export with explicit `profiles` (IDs only), `posts`, `post_media`, `post_polls`, `poll_options` and `poll_votes` arrays. It validates the known legacy schema, retains stable UUIDs and original timestamp strings, keeps legacy reply/media metadata and poll rows, and plans all posts as private by default until visibility reconciliation. It rejects unknown columns rather than dropping them; if the live legacy schema differs, extend the mapping after inspecting the authorized export schema. This function does not log personal content or perform imports. Target compatibility storage, media verification and actual source/target reconciliation remain blockers. Do not commit transfer bundles or source exports.

## Narrow provider retirement scope
Only Supabase, Google Cloud, Resend and fal.ai are in the lost-account refactor. GitHub, existing Cloudflare Worker `weizai`, and unrelated services stay unchanged. The preview branch disables new Google OAuth and linking even if the old environment flag is true, preserves linked-identity display and callback handling, stops client welcome-mail invocation, and makes the legacy optional welcome-email source return 410 without network or database writes. The actual deployed legacy Edge Function and old secrets are unchanged. Do not merge or activate this change in production until Google-only account recovery is verified; never auto-link by email. Registration verification/password recovery remain dependent on the old auth mail configuration until a trusted replacement is verified. Welcome-email delivery history remains intact. No new paid provider or service resources.

## Atomic identity result persistence
Migration 014 adds owner-only `apply_identity_decision`: event deduplication and state/revision update occur atomically, with session, workflow, version and sandbox binding checked under row lock. Stale attempts do not consume events; caller must re-fetch current provider decision before attempting a fresh revision. Never expose the SQL function to browser or grant it to profile/auth runtime. The earlier individual functions are retained for legacy lab tests; the integration must use the atomic path. The new test checks replay, cross-account event reuse, stale revisions, terminal transitions and privileges. Provider signature verification, current decision retrieval, revocation and real sandbox acceptance remain prerequisites. Didit free plan covers passive liveness, not active 3D; do not silently downgrade the existing active requirement or activate paid checks. No face photos, identity documents or raw reports stored by this migration.

## Restricted identity evidence workbench foundation
015 introduces an isolated encrypted vault for face photo, document front/back and necessary identity fields, linked to an attempt and separately granted consent. The seven-day ceiling is a provisional engineering upper bound, not an approved retention period; use the shortest necessary period or no raw retention. Explicit reviewer entitlement, enabled staff role, single-use case/session-bound MFA proof and audit protect case metadata. Revoked/expired records are omitted from metadata. AES-256-GCM binds ciphertext to attempt, category and key ID; key custody must be outside the database. The metadata function is owner-only, not yet exposed. No upload, raw-image viewer, bulk export, actual proof issuer, provider media retrieval, cross-border approval, purge job or real key is enabled. Expiry hides evidence but does not erase storage; enforce verified deletion (including provider copies and backups) before collection. Assess necessity, separate informed consent, alternative verification, minors and cross-border rules before deployment. Do not copy raw materials from Didit unless lawful and necessary. Existing badge UI and production unchanged.
