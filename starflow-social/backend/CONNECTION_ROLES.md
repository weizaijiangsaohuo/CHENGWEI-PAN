# Reproducible backend role setup
For a fresh isolated database, install the generated Better Auth SQL and business migrations 001-011, then 012. Run tests/012_backend_roles.sql before any credential provisioning. This step creates two restricted NOLOGIN roles, not executable login credentials. For the already initialized owner-controlled Neon staging branch, 012 corresponds to manual setup; do not replay CREATE ROLE statements there. Compare and validate existing roles instead. No password, token, live endpoint or customer data is stored here.
The business role may SET ROLE to the session gateway and through it the profile runtime, but must not inherit or reach the review gateway. Auth CRUD is confined to the seven auth tables, not sf_core. The test checks privileges and memberships; a separate login/driver/Worker test is still required before enabling any route. Do not enable the v2 feature switch in production, expose SQL, or place credentials in build variables or repository data. Existing production Worker and legacy data are unchanged. Do not provision managed Neon Auth, new compute or paid add-ons.
