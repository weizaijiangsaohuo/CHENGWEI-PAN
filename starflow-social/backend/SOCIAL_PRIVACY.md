# Social privacy phase 3 (laboratory only)
Follow requests require recipient approval; DM requires mutually accepted follows. Blocking removes relationships and hides messages; old messages retained, not erased. Communities private by membership, provisioned only by trusted migration owner for now. Staff roles default disabled; no role assignment, administrative actions, or MFA bypass. No real users or routes.
Before production implement concurrency-safe serialization of block/follow/DM transitions, privacy and abuse settings, request limits, private media, notifications/realtime, community moderation and membership workflow, verified session-bound administrator MFA step-up and append-only audit of actual authorized actions. The isolated model is deliberately stricter than the old website and should not silently replace old user behavior. No claim of E2EE. No automatic founder restoration. Test uses disposable Postgres. Passkey remains the existing Better Auth configuration; actual registration and assertion ceremony plus real iPhone/USB/NFC acceptance pending.
