# Authentication ceremony acceptance
TOTP test uses independent RFC 6238 codes derived from a synthetic enrollment URI, actual Better Auth registration/2FA endpoints, password-only denial, invalid code denial and valid-code sign-in. No real account, secret or device is used; never log enrollment URI or backup codes. Admin review proof issuance must bind a fresh verified ceremony to its exact authenticated session, purpose, expiry and replay ledger. The ordinary login TOTP test does NOT prove a fresh administrator step-up. Do not issue staff_stepup from an untrusted flag or simply because twoFactorEnabled=true. Passkey challenge tests previously passed; full registration/verification/signature tests and actual iPhone acceptance still necessary. No production handler, account or billable API.
