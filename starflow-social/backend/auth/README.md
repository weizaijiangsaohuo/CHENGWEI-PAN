# Better Auth isolated security laboratory
No production handler, credentials, signup or email delivery. Source is separate from existing Next.js runtime. Pin Better Auth and passkey 1.7.26 and pg 8.23.1; versions checked 2026-11-20. CI resolves transitive dependencies, audits, then tests disposable PostgreSQL only. Commit reviewed lockfile before integrating. No real Neon connection.
- Exact HTTPS relying-party origin, RP ID hostname, secure cookies and no cookie cache; username/password requires verified email; self-registration is disabled; passkeys require existing verified session and user verification (biometrics OR device PIN); both platform and roaming authenticators allowed. TOTP enrollment requires verification, backup codes encrypted. No Apple/Google OAuth, no automatic linking. No paid infrastructure plugin.
- Before enabling signup: implement real Brevo sender with atomic quota, Turnstile and anti-abuse, reserved-name checks, verified email ownership, password-reset/recovery tests; enforce admin MFA with server-side step-up independent of auth plugin (passkey flows do not necessarily trigger TOTP). Need trusted Cloudflare IP extraction and rate limit concurrency testing; bind authenticated session to sf_core.principals through server-only transaction. Run actual Neon/Workers integration, credential separation, schema review, lockfile and audit, passkey real-device tests. Do not log tokens or secrets.
- Authenticator device PIN fallback is valid WebAuthn; cannot guarantee Face ID on every login. KYC real-time scan remains Didit. Passkey-first signup is intentionally unavailable until secure account creation/recovery workflow is tested.
- No production migration or deployment without owner authorization and data recovery decision.
