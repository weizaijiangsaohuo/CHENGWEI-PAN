# Existing Worker preview composition
preview-runtime.mjs composes the pinned Better Auth factory and business HTTP handler, with separate request-scoped pg pools, expected direct Neon hostname, database and role checks, verified TLS, fail-closed preview flags and mandatory trusted Access authorization callback. No network is used by its unit tests. Cloudflare support for the selected driver, actual TLS/channel binding behavior and request lifetime still need a Workerd preview test; do not weaken TLS. The env host must be checked against the actual staging branch and credentials must be provided through runtime secrets only. No production origin, owner credential or pooled host. Never substitute a browser header or a static true callback for verified Access authorization. Before mounting in the existing Next.js Worker: commit a reproducible root dependency lock, integrate the actual Access verifier, verify preview audience and origin, and test on the authenticated preview URL; no new Worker required. Login, logout and regular TOTP endpoints are allowlisted for integration testing; account creation, OTP mail, recovery, passkey, admin proof/queue and websocket endpoints intentionally remain closed. Fresh staff step-up, passkey MFA policy and individual quotas must be verified before extending that allowlist. No existing UI or production routes changed.

Owner-only GET /api/v2/readiness verifies both configured role logins, restricted role attributes and the seven authentication tables' privilege separation using read-only catalog queries against both request-scoped pools. It rejects excessive privileges, missing grants, missing auth tables and access to the review gateway. It returns only {ready:true} if database, login identity and privilege probes match; otherwise 404/403/503, without exposing credentials, database names, or exception details. The same preview flag, origin and signed Access checks apply before either connection is opened. Passing this check proves connectivity and selected privilege invariants, not complete application readiness. The same probes run against real restricted roles in disposable PostgreSQL CI, including a temporary excess-grant negative test. No login credentials are created and no production feature switches are changed.

Owner-key alternative (optional, no Zero Trust subscription): see PREVIEW_ROUTES.md. The separate runtime secret is not a Cloudflare API token or an authentication signing secret. Both modes retain exact-host, default-disabled, no-production, same-origin and route allowlist checks. Verification is before pg pool construction. End-user sessions and admin MFA remain separate requirements.

## Enabled preview role attestation
Each enabled owner-authorized preview request now repeats the same restricted-role checks before creating the authentication handler or dispatching business operations. Authentication-only requests use only the auth pool; business requests check both request-scoped pools. Unsafe privilege changes deny service rather than rely on a previously successful readiness probe. The production flags and preview host rules are unchanged. The alternate attestation database name is a constructor-injected disposable CI fixture only; the deployed Worker uses the default neondb. This extra catalog overhead must be measured in the actual preview before enabling public traffic.

## Privileged function execution attestation
2026-11-21 read-only staging catalog checks found 17 SECURITY DEFINER functions in sf_core. Neither login could execute any directly; the delegated roles could execute only can_view_author(uuid) and resolve_auth_subject(uuid), respectively. Runtime attestation now rejects additional direct EXECUTE grants to all four roles and requires the intended delegated functions. Disposable CI rehearses temporary grants of registration issuer execution to each role and revokes them. No Neon grant or data changes. Live preview acceptance remains required.
