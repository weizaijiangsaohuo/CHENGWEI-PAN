# New-account provisioning lab
Migration 024 implements atomic creation of a new ordinary profile/principal and explicit Better Auth UUID binding, using a dedicated NOLOGIN role that has no direct admission, auth, staff or profile table grants. An owner-only short-lived admission and a verified active session are both required; replay and handle collisions fail without reusing an older principal. No ordinary signup can choose its own authority, import a prior account, or receive a role. No admission issuer or public route exists. CI runs synthetic SQL fixtures in a rolled-back transaction and a server adapter unit test. Runtime attestation rejects the new gateway membership on both existing login roles. No migration applied to Neon yet; keep production disabled until actual signup/verification/admission issue protocol, concurrent eligibility/revocation tests, free mail and secure credentials are ready. The user's legacy-account retirement request remains separate; no old data deleted by this work.
