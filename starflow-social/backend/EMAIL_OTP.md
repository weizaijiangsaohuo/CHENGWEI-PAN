# Email OTP (isolated, no delivery)
No SMS, WhatsApp, phone-number plugin or paid services. Separate Better Auth laboratory factory with allowlisted sign-in OTP endpoints, signup disabled by default, six digits/5 minutes/three attempts, keyed hash and rotating codes. Real email delivery is not implemented: callback captures codes in memory only in CI. Brevo OTP request builder never calls network. Shared 240 attempted emails/rolling 24h for existing link mails plus OTP, per-recipient three/hour and 60s cooldown; event deduplication and locks. Database owner only; no dispatcher grant yet. Before enabling issuance, use one durable outbox and atomic reservation, verified sender, canonical recipient keyed HMAC, global/IP/recipient abuse guards and Turnstile; reservations must commit before any mail call. Do not rotate live OTP on rejected quota requests. The OTP callback is not wired to the budget yet. Account linking and founder restore by email forbidden. Better Auth v1.7.26 two-factor sign-in hook covers password/username/phone only, not email OTP: isolated session hook refuses users with MFA or denied eligibility. Production requires trustworthy eligibility lookup for any staff roles (including disabled), concurrency-safe role and MFA changes with session revocation, audited session creation and other endpoints, no raw auth handler exposure, and assurance that lost access cannot be recovered with email alone. Do not expose OTP for privileged users. Actual fresh administrator MFA issuance is still pending. Existing password, TOTP, Passkey and recovery system unchanged. No original UI edits or production database access.
## Replacement transport gate
`services/mail-dispatch.mjs` is an internal send adapter, not a deployed endpoint. It requires trusted recipient resolution, explicit enablement, verified free-account status, a committed shared quota reservation and injected transport. It performs at most one send attempt and never reports provider acceptance as delivery. Timeout, rejection or ambiguous result cannot refund the budget or trigger automatic retries. The HMAC key is separate from API credentials. The free plan is documented at https://help.brevo.com/hc/en-us/articles/208580669-FAQs-What-are-the-limits-of-the-Free-plan ; the existing internal rolling cap stays 240. The trusted authorization, committed reservation, actual free plan verification and transport integration are mandatory; none are configured in the deployed Worker. No new paid resources, live sends or OTP issuance are enabled.
