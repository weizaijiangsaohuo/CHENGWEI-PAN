# Realtime and migration gates (isolated)
Incremental private message read: server cursor, bounded batches (100), database RLS, sequence allocated under transaction lock. Never treat cursor as authorization. No WebSocket, public endpoint, background polling or durable object created. Global serialization is intentionally conservative; benchmark contention, concurrent commit ordering, block races, revocation, reconnect and cache invalidation before release. No user content should be sent in push hints; reconnect must re-authorize every fetch. Existing local cache cannot be retroactively erased merely by RLS.
## Migration acceptance
The old Supabase project is not accessible through this repo. Do not use cached credentials or invent a backup. Owner must provide lawful exports or explicitly authorize a fresh start. Run dry-run against disposable database, preserve source IDs, compare counts, check duplicates/FKs, audit orphaned attachments, verify privacy and admin mapping; never auto-link accounts by matching email/handle. Reconcile existing media, scheduled tasks, notifications, communities, verification badges and moderation. Do not import old authentication credentials blindly. Keep source and backup immutable; cutover only after real Neon connection and rollback rehearsal. Never commit exported personal data. No live migration in this change.
