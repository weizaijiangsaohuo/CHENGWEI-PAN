# Realtime and migration gates (isolated)
Incremental private message read: server cursor, bounded batches (100), database RLS, sequence allocated under transaction lock. Never treat cursor as authorization. No WebSocket, public endpoint, background polling or durable object created. Global serialization is intentionally conservative; benchmark contention, concurrent commit ordering, block races, revocation, reconnect and cache invalidation before release. No user content should be sent in push hints; reconnect must re-authorize every fetch. Existing local cache cannot be retroactively erased merely by RLS.
## Migration acceptance
The old Supabase project is not accessible through this repo. Do not use cached credentials or invent a backup. Owner must provide lawful exports or explicitly authorize a fresh start. Run dry-run against disposable database, preserve source IDs, compare counts, check duplicates/FKs, audit orphaned attachments, verify privacy and admin mapping; never auto-link accounts by matching email/handle. Reconcile existing media, scheduled tasks, notifications, communities, verification badges and moderation. Do not import old authentication credentials blindly. Keep source and backup immutable; cutover only after real Neon connection and rollback rehearsal. Never commit exported personal data. No live migration in this change.

## Bounded catch-up pages
GET /api/v2/messages returns up to 50 RLS-visible messages, next sequence and hasMore (lookahead of one row). GET /api/v2/notifications accepts optional before=<notification UUID> and returns up to 50 visible notices, next (UUID or null), and hasMore. Cursor resolution uses the database timestamp and ID, not browser timestamps. Hidden or missing anchors return empty results; reset pagination when refreshing or after access changes. No automatic background polling or WebSocket transport is enabled by this change. The older client workflow remains unchanged. Real disposable PostgreSQL regression tests cover page boundaries, foreign cursors, duplicates, malformed input and blocking.

## Client snapshot integration (isolated)
The new inbox-sync.mjs library rebuilds bounded snapshots with an injected trusted same-origin transport, validates sequence advancement and membership, checks the principal before and after page batches, and discards invalid or cancelled responses. The caller must clear rendered state immediately when a refresh starts, on logout, account change or error, and must not retain earlier snapshots across authorization changes. No persistent cache, auto polling, real WebSocket or existing UI hookup. A snapshot cannot guarantee instant revocation after completion; it is only a bounded read at the time of the requests. The page budget signals truncation rather than silently claiming full history. No secret may be embedded in public JS. Unit tests run in existing UI CI.
