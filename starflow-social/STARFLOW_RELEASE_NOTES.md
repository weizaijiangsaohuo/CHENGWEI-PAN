# Starflow AI — 2026-10-10 功能扩展包

> 这是对现有 Starflow AI 项目的**增量代码更新包**，不是完整网站重建包，也不是全部需求已验收的声明。

## 本次实际开发内容

1. **发帖投票**：创建 2–4 个选项、1 小时至 7 天的截止时间、账号级单次投票、真实票数和比例。服务端原子写入与防重复投票。
2. **最多四图发布**：JPG/PNG/WebP/GIF，每张最多 5 MB，客户端预览、逐张移除、4 图网格与大图查看。多图入库调用事务化 RPC，单图和 50 MB 视频维持现有发布逻辑。
3. **社区**：创建公开社区、规则介绍、加入/退出、已加入成员发布社区帖子、查看社区专属内容流。真实数据库、RLS 和服务端 RPC。
4. **关注列表**：私密/公开列表、把自己已关注的账号加入列表、列表内容流与删除成员。私密列表访问由数据库 RLS 管理。
5. **创作者数据**：7 / 30 / 90 天真实发帖、收到的点赞/转发/回复、当前粉丝量与每日发帖柱状图。不伪造没有采集的浏览量和收入。
6. **认证审核**：管理员队列、蓝金灰审核和拒绝、撤销认证、审计日志。新增 `platform_admins` 角色表、`is_platform_admin` 和服务端审核函数；没有用户会自动成为管理员。
7. **内容审核后台**：管理员查看举报、标记已审核和删除违规帖子，均由数据库授权检查。
8. **搜索优化**：探索页支持数据库端正文搜索，`#话题` 支持跳转至探索。
9. **草稿保留**：未发布文本保存在当前浏览器本地存储，不会作为线上同步草稿跨设备同步。

## 部署路径：仅上传一个 ZIP

1. 请先确认备份或保留原仓库提交（GitHub 可还原）。
2. 把文件 **`starflow-release.zip`** 上传到 GitHub 仓库 `weizaijiangsaohuo/CHENGWEI-PAN` 的 **根目录**，替换同名 ZIP 后提交到 `main`。
3. `.github/workflows/starflow-zip-auto-update.yml` 会校验 ZIP、解压、执行 `npm run lint` 与 `npm run build`，只有通过后才将源文件提交到 `main`。此工作流不会自动删除旧文件。
4. 等 GitHub Actions 绿色通过，再检查 Cloudflare Workers 最新的部署是否 `就绪`。
5. 使用真实账号分别验证投票、多图、社区、列表、数据中心以及管理员页面。

**Supabase**：本次数据库所需的增量迁移已经在当前 Supabase 项目 `cmaqtimncblxywqbwbgl` 成功执行。ZIP 也附带迁移 SQL 供后续新环境迁移；**不要在当前生产数据库中重复手动执行**，也不要复制角色授权模板后随意赋予他人管理员权限。

### 管理员授权（尚待项目所有者确认）

目前管理员角色表没有任何用户，因此管理员后台在未授权时会正常显示“需要管理员权限”。项目所有者需要先确认登录账号的真实 UID，再在 Supabase SQL Editor 使用受信任的管理员角色授权，例如：

```sql
-- 仅由项目所有者完成；把 UUID 替换为已核实的本人账户 UID。
INSERT INTO public.platform_admins(user_id)
VALUES ('在此填写已核实的本人账号UUID')
ON CONFLICT (user_id) DO NOTHING;
```

不能通过客户端 UI 或普通 Supabase API 给自己授权。
